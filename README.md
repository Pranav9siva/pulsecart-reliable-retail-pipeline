# PulseCart: Reliable Retail Data Pipeline

An end-to-end portfolio project for batch and near-real-time retail analytics. It uses the original UCI Online Retail II transaction data, PySpark batch processing, Kafka event replay, PySpark Structured Streaming, Airflow orchestration, and DuckDB reporting.

## Original data

The bundled `data/raw/uci_online_retail_ii.zip` is from the [UCI Machine Learning Repository's Online Retail II dataset](https://archive.ics.uci.edu/dataset/502/online+retail+ii). The dataset was created by Daqing Chen and contains 1,067,371 transaction lines from 1 December 2009 through 9 December 2011. UCI publishes it under the Creative Commons Attribution 4.0 International license.

Attribution: Chen, D. (2012). *Online Retail II* [Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C5CG6D. Dataset page: https://archive.ics.uci.edu/dataset/502/online+retail+ii.

The transaction rows are real historical records. The JSON envelope, event IDs, and Kafka replay are generated by this project from those rows to demonstrate an event pipeline; they are not an original live event feed.

The extracted source profile contains 1,067,371 rows: 525,461 from 2009–2010 and 541,910 from 2010–2011. `customer_id` is blank on 243,007 rows, and five rows have a negative unit price; those five are rejected by the batch validation rule. The source contains 22,951 rows flagged as returns or cancellations.

## Architecture

```text
UCI XLSX workbook
       │
       ▼
Python extraction ──► canonical CSV + source manifest
       │
       ▼
Airflow DAG ──► PySpark batch transforms
                       ├── bronze: raw typed source snapshot
                       ├── silver: validated order lines
                       ├── quarantine: rejected rows and reasons
                       └── gold: dimensions and analytics marts

Canonical CSV ──► Python replay producer ──► Kafka topic: retail.order_events
                                                  │
                                                  ▼
                                    PySpark Structured Streaming
                                      ├── valid order events
                                      └── quarantined events
                                                  │
                                                  ▼
                                       Parquet + DuckDB reports
                                                  │
                                                  ▼
                                       Streamlit dashboard
```

## Run locally with Docker

Requirements: Docker Desktop with Compose, an internet connection for the first image build and Spark's Kafka connector download, and enough disk space for the workbook plus Parquet outputs.

From this project directory:

```powershell
docker compose up --build -d
docker compose logs -f airflow
```

Open the [Airflow UI](http://localhost:8081) and [sales dashboard](http://localhost:8501). Airflow standalone prints the local admin credentials in its startup logs. Trigger the `pulsecart_retail_batch` DAG to run extraction, batch transforms, quality checks, and report generation in order. The DAG is manual by design so a portfolio demo does not reprocess the full snapshot every day.

The source archive is included. To re-extract it or retrieve a fresh copy, the task runs `pulsecart extract`; the downloader also works when the archive is absent.

## Run the near-real-time replay

Create the topic once, then start the streaming consumer in one terminal:

```powershell
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh --create --if-not-exists --topic retail.order_events --bootstrap-server kafka:9092 --partitions 1 --replication-factor 1
docker compose exec airflow python -m pulsecart.cli stream --bootstrap-servers kafka:9092
```

In another terminal, publish a paced sample of 5,000 real historical rows as JSON events:

```powershell
docker compose exec airflow python -m pulsecart.cli replay --limit 5000 --batch-size 250 --interval 1 --bootstrap-servers kafka:9092
```

The producer publishes to `retail.order_events`. The stream validates schema and required fields, deduplicates by `event_id` within a two-day event-time watermark, and writes valid events and rejects to separate Parquet paths under `data/lake/streaming/`. Stop the consumer with Ctrl+C after replay completes. To replay from the beginning without touching existing checkpoints, choose a fresh topic name and pass it to both commands with `--topic`.

## Run commands without Airflow

The Docker image is the supported path on Windows because it supplies a compatible Python and Java runtime. If running on Linux or macOS directly, use Python 3.10–3.12 and Java 17, then install the project:

```bash
python -m venv .venv
# Activate the environment, then:
python -m pip install -e .
pulsecart extract
pulsecart batch
pulsecart quality
pulsecart report
```

For local Kafka access, start the `kafka` service with `docker compose up -d kafka`; host processes connect to `localhost:29092`. The streaming command downloads the matching Spark Kafka connector from Maven on first use.

## Sales dashboard

The Streamlit dashboard reads the generated daily sales, top product, quality, and summary reports. It includes a date range filter, country selector, sales and return metrics, daily revenue trend, country breakdown, and pipeline quality status. Start it with Docker Compose and open [http://localhost:8501](http://localhost:8501) after the batch DAG has produced the reports.

## Data layers and models

| Layer | Dataset | Purpose |
|---|---|---|
| Bronze | `bronze/online_retail_ii` | Source snapshot with ingestion timestamp and source row identifiers |
| Silver | `silver/order_lines` | Parsed timestamps/numbers, normalized labels, signed return quantities, calculated line revenue |
| Quarantine | `quarantine/batch` | Invalid source records with a validation reason |
| Gold | `dim_product`, `dim_customer` | Product and customer dimensions |
| Gold | `mart_daily_sales` | Daily order, return, revenue, and unit metrics by country |
| Gold | `mart_product_performance` | Product sales and returns |
| Gold | `mart_customer_summary` | Customer order and net revenue metrics |
| Streaming | `streaming/retail_order_events/valid_orders` | Valid replayed order events, partitioned by event date |
| Streaming | `streaming/retail_order_events/quarantine` | Invalid event payloads plus Kafka offsets and rejection reasons |

`customer_id` is intentionally nullable because anonymous purchases exist in the source. Cancellation invoices and negative quantities are retained as returns; revenue is signed so net sales account for them.

## Reliability and data quality

- The raw workbook remains unchanged; extraction writes a canonical CSV and a manifest with row counts and SHA-256 checksums.
- Source row IDs are stable across runs, so identical line items are not incorrectly collapsed.
- Batch validation routes bad invoice IDs, stock codes, timestamps, quantities, and prices to quarantine.
- The quality task checks source-to-output reconciliation, unique row IDs, required silver fields, and a configurable quarantine-rate ceiling.
- Airflow retries failed tasks and runs only one instance of this batch DAG at a time.
- Streaming uses Kafka offsets, Spark checkpoints, a two-day event-time watermark, and stable event IDs to support restart and duplicate handling.

## Verified demo run (2026-11-10)

- The Airflow batch DAG completed successfully against all 1,067,371 source rows: 1,067,366 accepted and 5 quarantined. Reconciliation, uniqueness, required-field, and quarantine-rate checks all passed.
- The analytics summary contains 41,938 orders, £19,445,926.708 net revenue, 11,672,565 units sold, and 1,064,078 units returned.
- A Kafka replay of 5,000 historical rows produced 5,000 valid streaming records and 0 quarantined events.
